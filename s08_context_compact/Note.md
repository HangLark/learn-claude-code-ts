# s08：Context Compact

## 核心结论

每次模型调用前，Harness 按固定顺序把 `messages` 转换成更小但可恢复的表示；只有确定性压缩仍不够时，才用模型摘要替换历史。

```text
可发送上下文 = prepare(messages, activeRequest)
```

## 核心数据

核心状态仍是已在 s01 展开的 `Anthropic.MessageParam[]`，本章新增的是它的两种派生表示：

- **持久化引用**：完整 transcript 或工具输出写入磁盘，消息中只保留路径、标记和预览。
- **摘要消息**：用一条 user message 保存当前请求、事实摘要和完整 transcript 路径。

`ContextCompactor` 持有压缩配置，包括总字符预算、单批工具结果预算、保留的最近结果数和 reactive tail 长度。这些阈值不随循环变化；`estimate(messages)`、待归档中段和待缩短结果都是由当前消息状态派生的数据。

`activeRequest` 单独传入压缩器，因为压缩后的历史必须继续明确表达本轮真正要完成的请求，不能只依赖模型摘要。

## 数据流

```text
原始 messages
  → 1. 最新工具结果批次超限
       → 大结果写入 .task_outputs
       → content 替换为路径 + 预览
  → 2. 消息数超限
       → 完整历史写入 .transcripts
       → 中段替换为归档标记
  → 3. 估算仍超限
       → 较早且已被模型消费的结果替换为持久化路径
       → 必要时继续缩短最大结果
  → 4. 仍超限
       → 保存 transcript
       → 模型生成事实摘要
       → [当前请求 + 摘要 + transcript 路径]
  → 作为下一次模型调用的 messages
```

磁盘文件是完整数据，消息中的路径和预览是派生数据；缩短上下文不会删除恢复原始观察所需的信息。

## 关键约束

- 四个阶段的顺序固定：先持久化和裁剪，再调用有损的模型摘要。
- 压缩切点不能落在 `assistant(tool_use)` 与紧随其后的 `user(tool_result)` 之间。
- 旧工具结果只有在后续 assistant 消息已经消费后才能替换；最近结果优先保留。
- 摘要必须把当前用户请求与 conversation summary 分开，并把摘要标记为参考数据。
- 已持久化结果再次压缩时复用原路径，不能把预览当作完整输出重复保存。
- 模型主动调用 `compact` 时，必须先执行并回填同一响应中的整批工具，之后才能替换历史，避免重放副作用。

## 闭环变化

正常的“有工具则继续、无工具则停止”没有改变，但模型调用前增加了统一的 `prepare` 阶段。若 API 仍返回上下文过长，Harness 会保留最近的完整消息边界并 reactive compact 一次，然后重新进入同一轮；第二次失败才向外传播。
