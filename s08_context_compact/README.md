# s08: Context Compact — 先整理，再总结

> 上下文总会满；先做可恢复的确定性压缩，最后才调用模型摘要。

每次调用模型前，s08 按固定顺序处理消息：

1. 最新一批工具结果超过预算时，把大结果写入 `.task_outputs/tool-results/`，上下文保留路径和预览。
2. 消息超过 50 条时，把中段写入 `.transcripts/`，保留头尾与归档标记。
3. 估算字符数仍超限时，把较早、模型已经看过的工具结果替换为可恢复路径；必要时再缩短最大的结果。
4. 仍然超限才调用模型生成事实摘要，并明确保留当前用户请求与完整 transcript 路径。

压缩切点不会拆开 `assistant(tool_use)` 与对应的 `user(tool_result)`。若字符估算仍不准确、API 返回 `prompt_too_long`，harness 会保留最近 5 条消息并补救一次。

模型也可以调用 `compact` 主动请求压缩。harness 会先完成该响应中的整批工具、回填所有结果，再压缩闭合后的历史，避免重复副作用。

## 运行

在仓库根目录准备 `.env` 后执行：

```sh
pnpm s08
```

让模型连续读取多个较大文件，观察 `.transcripts/` 与 `.task_outputs/tool-results/` 中的可恢复记录。按 `Ctrl+C` 退出。

s09 会把需要跨压缩、跨会话保留的信息移入独立记忆系统。
